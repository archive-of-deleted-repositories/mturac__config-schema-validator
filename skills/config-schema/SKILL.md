# config-schema

Infer a JSON Schema from an existing config file and save it for future validation.

## Trigger

`/config-schema [file]` or when user asks to generate, infer, or extract a schema from a config file.

`[file]` is required. If not provided, ask the user which file to analyze.

## Steps

### 1. Read the Config File

Read the specified file. Determine its format from extension:
- `.json` → parse as JSON
- `.yaml` / `.yml` → parse as YAML (treat as key-value structure)
- `.toml` → parse as TOML (treat as key-value structure)

If file cannot be parsed, report the parse error and stop.

### 2. Infer Schema

Walk the parsed structure recursively and infer a JSON Schema (Draft 7):

**Type mapping:**
| Value type | JSON Schema type |
|---|---|
| string | `"type": "string"` |
| integer | `"type": "integer"` |
| float/number | `"type": "number"` |
| boolean | `"type": "boolean"` |
| null | `"type": "null"` |
| array | `"type": "array"`, infer `items` from first element |
| object | `"type": "object"`, recurse into `properties` |

**Required field heuristic:**
- Mark a field as required if it appears at the top level of a known config type (e.g. `services` in docker-compose, `jobs` in GitHub Actions)
- For unknown configs: mark ALL fields present in the file as required (conservative default)
- Add a comment note: `// Fields marked required based on presence in source file`

**Additional inferences:**
- If a string value matches a semver pattern → add `"pattern": "^\\d+\\.\\d+\\.\\d+"` 
- If a string value looks like a file path → add `"description": "File path"`
- If an array has a consistent element type → set `items` schema accordingly
- If an integer is 0, 1, or 2 and the key contains "level", "severity", or "rule" → add `"enum": [0, 1, 2]`

### 3. Build JSON Schema Document

Output schema structure:

```json
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "$id": "<filename>.schema.json",
  "title": "<filename> configuration",
  "description": "Auto-inferred schema from <filepath> on <date>",
  "type": "object",
  "required": [...],
  "properties": {
    ...
  },
  "additionalProperties": false
}
```

Set `additionalProperties: false` to catch unknown fields in future validations.

### 4. Save Schema

```bash
mkdir -p .config-schemas
```

Save to: `.config-schemas/<filename>.schema.json`

Where `<filename>` is the base name of the source file (e.g. `docker-compose.yml` → `.config-schemas/docker-compose.yml.schema.json`).

### 5. Output

Print the inferred schema to the conversation (truncated if > 100 lines — show first 80 lines + "... (see .config-schemas/<filename>.schema.json for full schema)").

Then print:

```
Schema saved: .config-schemas/<filename>.schema.json
Fields: X required, Y optional
To validate future configs against this schema, run: /config-validate
```

### 6. Integration Note

The config-scan skill checks known config types against hardcoded schemas.
Custom schemas generated by this skill are also checked during `/config-validate` if a `.config-schemas/<filename>.schema.json` exists for that file.
